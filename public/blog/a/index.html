blog / Running a Minecraft Server without paying a cent (and having full control)
📅 2025.02.05 · ⏱ 8 min read

#ChroniclesOfBrokeKid

Since 2019, I have been toying the idea of running a minecraft server of my own. My elementary classmates would play various multiplayer games, but minecraft was prominent.

April of 2020 was the first taste I had of running a minecraft server, My parents lent me a barely alive but working EEE Laptop that was running on Windows 7. I had no much idea what was Java even about, but I knew I needed Java to host a server. Driven with the thrill of running my own server, I installed Java 8, downloaded the Minecraft Server JAR, then ran it and prayed. It launches! So I excitedly pulled my phone and my sibling's tablet, opened multiplayer tab and... none?? I was confused, I didn't knew the concept of IP Address and Ports back then, it left me frustrated that gave me no hope.

Then next year I discover Termux. And honestly I only discovered it first from goofball YouTube channels that shows how to launch a phishing sites to gain credentials, turns out its more much than that. Here I understood the fundamentals of networking, how commands and scripting works and building things At this period I would mostly just mess around and figure out how things work. And it can run OpenJDK.

"OpenJDK Java? You say?" I was intrigued back then that it was possible to run java on phones back then, it was like telling people back in 1900's that putting large fans to a machine can make it fly like a bird. which is absurd because no one in hell can fly except animals that has wings! But hell they did, just like running an OpenJDK runtime on a phone

Though, I want to be clear, Android does use Java in system components and applications. But it does not use OpenJDK Runtime which what Minecraft uses. Instead it utilizes DalvikVM and replaced by ART (Android Runtime) on 2014, it is optimized for low-power devices, like a phone. And both aren't even the same at all. OpenJDK takes .jar files directly while ART requires a specific compiler to take java files into .jar then compiles into .dex files, then finally take that .dex to become an odex that becomes a native .oat Linux Binary. So much process to go through!

But unfortunately, at this period of time, OpenJDK on phones was still at its infancy. People reported crashes and unexpected behavior. Worse case was that my main phone was still weak, A Samsung J2 Prime. Yes, I did use J2 Prime as my main phone back then, and it lasted way longer compared to my mid-end phones from 2018.

But there were also sites like Aternos that allows you to host Minecraft Server for free, but not free "As in free beer." There was a time limitation that you had to watch ads each time you increase time. This was no problem in desktops, you just have to switch window to browser and done. No problems! But this was an immensely painful process being on an old J2 Prime, I have to close Minecraft, open my browser, wait for website to load, watch ads, then open minecraft and wait for almost 2 minutes to finally get back. This was an absolute painful process that takes almost 10 minutes each 30 minutes, so I only get 40 minutes of playtime instead of an uninterrupted hours of gameplay!

I knew I need to do something. And the solution is quite literally outside the box.

Google Cloud Shell

There were discussions floating around that a free cloud server exists, it sounded too good to be true at first, until when I tried it myself, it was too great, 8GB of RAM and 2 CPU cores and 5GB of home storage, just enough for things to run, but I encountered a problem ofcourse.

Problem #1: Google SDK was big.

Installing the SDK counterparts floats around 1GB including the "alpha" components that I'm not really sure what's its even made off. What I do know is that I only need the gcloud cloud-shell ssh command. There wasn't really any known way to strip the components to only contain what's needed for cloud-shell as its a big behemoth that I don't want to spend my energy on. So instead, I had to think uniquely for solutions.

Solution #1: Remote to my aunt's phone to access gcloud

My aunt had this mid-end phone from 2018, so it was packed with 128GB of storage that may not sound alot for anyone, but for me who used a J2 Prime for years, it was massive. Following the tutorial kcubeterm provided, I got inside. But, how do I access it through my phone? I could've opted to use SSH. But well, there is two problems.

  • remote shell inside remote shell is twice unreliable
  • Like any typical person, she goes to work. And there is no way in hell I can enter a remote shell if their phone is on cellular data.

Thankfully, there is a solution: tmate tmate is quite literally when SSH and Tmux have a child. It can retain a session while being able to attach and detach anytime, best thing is that it doesn't need port forwarding! tmate will provide a link that you can ssh to or use a web terminal.

Doing a test-flight, it worked just enough, it takes like half a second to appear on your screen what you typed, but it wasn't really jarring that it felt bad.

On real world.. It was that bad. I forgot to account Android have battery optimizations like when screen is off, so it would constantly disconnect. Cellular data is also turned off, I could've probably deliberately send a signal to wake up the screen every minute, but well that's outside the line I can do, she'll probably think her phone have malware.

So I have to think again.

Solution #2: Use a Linux VM on a small Computer Shop and remote into it

please don't do this, this is absolutely dumb and stupid! I immediately stopped afterwards.

Few blocks away from our house, a neighbor owns a computer shop, though its still on ancient times where you have to slide a peso coin. Aside from the smelly headsets and oily mouse, Computer Caffe's are the place to go when you don't have a computer and you want to play games. But I had a very different idea in mind.

The computers ran on Windows 7, somewhat old for 2023 but VirtualBox and Zerotier still works. First, I installed VirtualBox, then installed Alpine Linux on it. The good thing about ZeroTier is that it supports bridging between VirtualBox's virtual network that allowed it to be directly accessable in the Zerotier network without dealing of NAT issues.

And so far, it works, the problem is that it works. My puny brain forgot what I was doing was technically tresspassing, so I stopped.

Solution #3: Just put it on external storage and write a wrapped bash script.

After all of that troublesome mess, I decided to look for local solutions. One big gripe of Android is that execute permission was not allowed anywhere that a user can access such as the /sdcard path which where is files usually was stored. Nor symlinks is even allowed.

But hold on, Google Cloud SDK is literally just a python program. It is interpreted and no native binaries with execution permission is required..

While seemed like a dumb idea, I gave it a shot. I copied the folder onto my 14GB memory card where termux has access to. Wrote a wrapper bash script that contains

/storage/6AF2-6798/Android/data/com.termux/files/google-cloud-sdk/bin/gcloud $@

Stored the wrapper script on where termux can execute it and then..

Welcome to Google Cloud SDK!

It works.

Yipie, now we get inside! Now what?

The plan is simple, we run a Minecraft server, make it accessable to everyone, and the world is happy! right? right???

As expected from this setup, its not that easy.

Problem #1, Is this even legal?

Technically, Yes. Google cares only about three things

  1. Don't do cryptomining.
  2. Don't use this to do anything that abides the law.
  3. We will watch whatever you do.

We are not hosting a malware, or using it to launch a cyberattack nor be [[watching porn on this cloud server]](you shouldn't consume porn in any form! please consider seeking help if you are suffering from porn addiction!). Instead, we are hosting a multiplayer game! But this isn't the real problem.

Problem #2: The server isn't publically accessable by anyone

Since we are on free tier. Google Cloud Shell does not offer port forwarding publically, that means we can't just type 69.67.240.69:19132 directly in Minecraft and be happy about it. I can't even connect to the server!

That sucks, 8GB RAM is wasted on this thing. But to hell with it, I won't give up making this publically accesable!
